# 战术角色关键属性实验

本功能在当前战术、阵容和比赛环境上，只改变一名首发球员的一项属性，并用相同随机种子进行配对比赛。它用于回答“这套战术中的这个位置／角色，对哪些属性更敏感”，而不是提供脱离战术和对手环境的固定属性表。

带真实结果示例图、验证范围和源码构建步骤的评审说明见 [PR 说明与运行示例](ROLE_ATTRIBUTE_PR.md)。

## 使用方法

1. 在战术板载入 FMF、存档战术或自行编辑战术与首发。
2. 点击战术板顶部的“运行角色关键属性分析”。
3. 勾选一个或多个首发位置（也可一键全选 11 人），再设置属性范围、属性提升点数和探索／验证场数。
4. 默认使用当前固定对手。需要多对手实验时，先在随机对手战术设置中导入 2–8 套战术，并开启统一客队属性，然后选择“客队战术池全部战术”。
5. 点击“开始分析”，在实验结果页查看实时进度、推荐总览和各属性明细。
6. 点击“导出独立报告”可保存一份自包含 HTML，离线打开或打印。

属性提升默认是 3 点，可设置为 1–19；测试值不会超过面板值 20，原值已经为 20 的属性会跳过。首次试跑建议只选一个位置、角色候选四项、探索 4 对和验证 4 对，确认配置后再扩大范围。

## 实验与推荐规则

- 探索和验证使用互不重叠的随机种子。
- 新实验采用双榜筛选：每位置按总收益与每点敏感度各取最多 K 项候选，去重后验证，最多 2K 项。总收益线默认 0.02，每点筛选线等于总收益线除以计划提升点数。“全部属性完整验证”会评估所有已验证属性，不再受探索候选上限限制。历史实验沿用原规则，保持续跑任务一致。
- 多对手模式逐套运行，并先在同一个种子内等权平均各对手的变化，再计算总体均值和标准误。
- “实际总收益”按本次实际提升后的场均 xG 差变化排序；“每点属性敏感度”把收益除以实际提升点数，便于比较接近 20 时只能少量提升的属性。
- 独立验证完成且均值为正时标为“初步关注”；探索和验证总收益均达到候选线，或每点收益均达到每点筛选线，标为“一般推荐”。“稳定推荐”还要求探索和验证总收益均达到强候选线、至少 60% 验证种子为正、至少三分之二对手／档位组合为正、均值减四倍标准误大于零，并达到用户设置的稳定推荐参考配对数（默认 8，可设 2–200）。参考配对数仅影响等级，不会自动增加比赛数，也不阻止一般推荐。
- 候选收益线、强候选收益线、每位置候选数和总览推荐数都属于本次实验设置，不是硬编码的普遍结论。

报告同时展示进球、失球、xG、xGA、控球、射门、射正、传球成功率等角色相关球队指标，以及均值加减四倍标准误的保守区间。该区间影响新实验的稳定等级，不淘汰初步关注和一般推荐，不是严格置信度或准确率保证。总览直接展示等级、完成配对数与波动提示；验证未完成的项目不赋予正式排名。每点效果是本次区间的平均效果，不能外推成属性每增加一点的固定收益。多个属性同时检验和排序仍可能产生偶然领先，名次不证明相邻项目有显著差异。

## 代表球员与标准档位

“当前球员实际属性”保留当前首发的完整属性组合，只提高被测属性。“标准属性档位”会把被测属性分别放在若干基准值上测试，默认是 8、12、16，适合观察同一角色在不同属性区间的边际敏感度。标准档位不是完整的标准球员模型，其他属性仍来自当前首发，因此报告结论仍需结合球员和战术环境解释。

## 数据与可移植性

代码不依赖固定盘符、用户名或开发机路径。实验输入、日志和报告继续使用程序现有的本地数据目录；Git 仓库只包含公开源码、测试和本文档，不包含游戏资源、存档、构建产物或个人诊断文件。

取消采用安全停止：正在运行的原生比赛先释放并保存已经完整通过校验的场次，完成数可能在短时间内继续增加。取消后的实验可以使用现有“继续未完成场次”功能恢复，已完成配对不会重复运行。

## 验证

提交前运行：

```powershell
python -m unittest discover -s tests -v
python scripts/export_source.py
```

修改比赛执行、阶段切换或取消逻辑后，还应使用自己的私有引擎数据验证：标准档位多阶段实验、探索结束时取消、取消后续跑、逐场回读和最终报告排序。

## 在其他 Windows 电脑构建与验证

从官方 Releases 下载 v1113 EXE，安装 Python 与系统 .NET Framework C# 编译器后，可在仓库根目录运行：

```powershell
python scripts/repackage_release.py --release-exe "官方v1113.exe" --output "dist/角色属性分析.exe"
```

脚本核验官方 EXE 和内嵌资源的 SHA256，重新编译当前启动器，打包当前 Python/UI 源码和官方自带运行时。生成的 EXE 无需使用者另装 Python；需要本地完整兼容的 FM27 游戏安装。游戏路径自动查找或手动选择，数据保存在当前用户本地目录。

此流程复用官方原生引擎宿主，不编译 native 修改；需要构建 native 源码时使用 DEVELOPMENT.md 中的 prepare_private.py、build_native.py 和 build_exe.py。prepare_private.py 现已接受官方 v1113。不要把私人存档或游戏资源提交到 Git。

可用隔离数据目录执行实机冒烟测试（需本机游戏，运行完整比赛）：

```powershell
python scripts/smoke_attribute_research.py --exe "dist/角色属性分析.exe" --game-root "游戏安装目录"
```
