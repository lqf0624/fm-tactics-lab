## 中文汉化会不会因换机失效

换机本身不会使存档失去中文或改变号码。显示综合使用存档完整姓名、能核对的游戏导出别名及游戏词库；用户导入的匹配译名可覆盖显示。没有可靠匹配时保留原名。

本次4月8日存档在**没有游戏词库**时，1452条显示记录中只有26条有中文；补入同一游戏的词库后，无需复制旧缓存，自动重建为1411条中文。可见只拷EXE或存档，不能保证原来的中文覆盖。球衣号码仍由存档读取。

词库位置为所选游戏根目录下的 `shared/data/database/db/<版本>/<版本>_fm/lang_db.dat`，程序选取存在词库的最高数字版本。换机需保留与原环境相符的游戏及汉化资源。只改皮肤、语言设置或其他位置的第三方补丁，未必能被该读取方式识别；本次没有逐个测试第三方补丁。英文 Windows 上界面会按当前语言逻辑显示英文，不代表存档损坏。

Nico Williams 在旧的UI验收原始记录中也是英文，和本次结果一致。此前文档“55名首发全部中文”已更正为54名有中文、1名原名；不将词库覆盖率说成100%。

## 新电脑需要什么

1. Windows x64、能运行本 .NET Framework 启动器的系统，以及 Edge、Chrome 或可用默认浏览器。无需另装 Python、Node 或编译工具。
2. 安装本版支持的 Steam FM27，并启动、登录拥有游戏的 Steam 账号。本次实赛引擎为 `27.0.1+2503222`；存档覆盖表中两种构建。Epic、新引擎及其他存档构建不在本次通过范围。
3. 可供原生进程加载的 Microsoft VC++ x64运行库。实际模块取自系统的 `MSVCP140.dll`、`VCRUNTIME140.dll` 和 `VCRUNTIME140_1.dll`；Python子目录中的运行库不能等同于所有游戏进程依赖已配齐。
4. 在顶部引擎设置重新选择包含 `fm_Data` 与 `shared` 的完整游戏目录；在存档页重新选择该电脑上的 `.fm`，等待首次解析。

测试中有一次退出82：日志明确指出无法找到Steam会话和安装目录。原因是测试沙箱的用户环境隔离；保持程序、资源和PATH不变，在正常用户会话重跑即成功。普通用户无需因此以管理员身份启动软件。本次结果也说明“静态兼容检查通过”不等于“Steam会话与完整比赛都已验证”。

## 旧实验和手工设置如何处理

功能可重新使用，与旧数据是否迁移是两件事。只拷 EXE 不会自动带走实验、人工译名、浏览器草稿、对照方案或专人指令。

- 被测本地交付版的数据在 `%LOCALAPPDATA%\FM27TacticsDesktop_LocalEdition`；本PR的官方源码构建保留原有 `%LOCALAPPDATA%\FM27TacticsDesktop`；使用 `--data-dir` 时以实际目录为准。
- 需要保留资料时，关闭工具后备份原始 `.fm`、该数据目录，以及另存到外部的文件。重要战术另存完整工具 JSON；FMF不包含所有工具配置。
- 数据目录中的 `save_library`、`runs`、用户译名文件和 `native-source-plan.key` 等是相关资料。浏览器草稿还受浏览器配置与本地服务地址影响，单独复制服务器数据不能保证恢复草稿。
- 新机重新指定游戏和存档路径。完整一键备份/恢复仍未实现，本次未把“整套旧资料搬迁”作为已验收功能；不要用测试结果覆盖这一限制。
