# 本地数据备份与恢复

关联需求：[PRD 的 A8](../PRD.md#6-验收标准)。本页是后续开发规格。v1114.4 已有实验摘要暂存、续跑、完整方案 JSON 和逐场 CSV；整份备份与还原仍待实现和演练。

## 数据范围

官方源码构建的默认应用数据根目录为 `%LOCALAPPDATA%\FM27TacticsDesktop`；此前本地交付版为 `%LOCALAPPDATA%\FM27TacticsDesktop_LocalEdition`。`--data-dir` 可以指定其他目录，备份应以当前实例实际使用的根目录为准。游戏安装目录和原始职业存档可能另在其他磁盘。

| 对象 | 备份与恢复要求 |
|---|---|
| 战术和操作状态 | 保留工具自己的自由／存档草稿、对照战术、选队和其他已保存设置，含按球员唯一 ID 保存的针对性指令。当前草稿与对照使用浏览器本地存储；恢复时即使本地服务端口改变也应能载入 |
| 存档资料 | 保存 `save_library/` 中的存档绑定、原文件指纹、已导入资料、`player_display_imports.json` 等人工修订。按存档身份恢复。允许重新生成的索引和词库缓存要在清单中标识 |
| 实验及其证据 | 保存 `runs/` 各实验的摘要与最新有效进度、比赛输入、种子、`provenance.json`、运行校验凭据、逐场日志、历史姓名快照及已有的结果。遇到 `summary.pending.json` 时，核对它是否代表更新的检查点 |
| 方案校验、导出与配置 | 保存本地方案校验所用的 `native-source-plan.key`，恢复后验证原方案能载入。保留工具数据目录下的用户导出物和必要设置；游戏安装路径和外部文件路径须在恢复时重新验证。密钥及原始私有数据仅留在本地备份中 |
| 原始 `.fm` 存档 | **建议默认只记引用和 SHA-256**，备份清单明确标注「外部文件」，并提供显式包含原档的选项。恢复到新机器时可重新定位同一指纹的原档；缺少原档时保留可独立查看的历史结果 |
| 可重建内容 | 程序解包目录 `releases/`、浏览器缓存、临时文件和可重新提取的游戏资源可省略。保留应用草稿所需的数据不应依赖复制整套浏览器资料。用户另存到工具目录外的 CSV、JSON、FMF 在清单中说明覆盖范围 |

## 操作约定

1. **创建。** 用户选择本机目标目录。列出数据类别、预计大小、应用版本、原档包含情况。默认由用户手动创建；保留轮数和定时频率尚未约定。
2. **一致性。** 使用一致的已落盘检查点。运行中发起备份时，可等待一场比赛结束并固定边界，或提示等待当前实验结束；清单记录可恢复到的场数。写临时包，逐项校验成功后才将其标记为可恢复。保留上一份有效备份。
3. **校验。** 清单记录备份格式版本、生成时间、相对路径、大小和 SHA-256。备份、恢复均核对清单；空间不足、文件损坏或条目缺失时，显示出错对象与可重试步骤。
4. **恢复。** 默认还原到新的本地数据目录，先校验，再载入。用户选择覆盖已有数据时，先列出受影响内容并留存回退副本。原档改名或移动时按指纹重新绑定；内容不同则作为另一份存档处理。

## A8 验收用例 · 全部待实施验证

| 用例 | 通过条件 |
|---|---|
| B1 空目录恢复 | 用包含两份赛季存档索引、一个草稿和一个对照的样本做备份。换目录启动后，切换两个模式，球员译名、指令归属、草稿与对照均可重现；签名方案可载入 |
| B2 完赛与中断 | 同时备份一项已完成及一项中断任务。恢复后逐场比分、种子及日志哈希一致；中断任务只补未完成场次。存在更新的暂存摘要时，以可校验的最新进度为准 |
| B3 故障与冲突 | 分别模拟磁盘空间不足、备份中断、篡改一份日志及恢复目标已有数据。界面指出错误或冲突；失败后原数据和上一份有效备份仍能打开 |
| B4 外部存档 | 分别验证“仅引用”和“包含原档”。前者在原档缺失时提示重新定位，后者可从备份还原。相同文件名但指纹不同的档不会串联 |
