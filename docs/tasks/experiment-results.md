# 针对性指令、历史结果与摘要占用

对应 [A5、A6、A7](../../PRD.md#6-验收标准)。进度：v1114.4 已在 Windows 打包版、Edge 和原版引擎上验证；v1114.6 PR #19 补充跨存档指令隔离与单场复测来源修复。完整本地备份另见 [A8 的待办](../LOCAL_BACKUP.md)。

## 进度与证据

- 在测试副本中让另一进程持有 `summary.json` 的读句柄并禁止重命名。5 路并行同时测试阿森纳和南安普顿，共 8 场。占用期间实验达到 8/8，解除占用后正式摘要自动补齐。
- 给松木玖生设「总是逼抢」，给中锋位置设盯人。检查两队各自主客场的比赛输入，松木的设置命中本人，阿森纳相同名单序号未继承该设置。
- 用户此前续跑的 36 场实验有 36 个唯一场次，36 份终场日志的哈希全部吻合，失败记录为零。历史页面与 CSV 已显示「塔米·亚伯拉罕」「约翰·麦金」及中文位置。这项实验使用当时选定的 18 支对手。
- 新回归验证界面及三条后端名单载入路径：换存档或旧来源未知时清空球员 UID 指令，同存档重读保留；位置指令保持不变。比赛输入生成还会检查指令所属存档，阻止另一生涯的相同 UID 继承指令。
- 对原场次 `A_2_H`、`B_0_A` 分别请求复测，落盘摘要准确记录原实验和场次编号，主客方向不变，种子与原实验互斥。上述新增回归先复现旧行为失败，修复后通过，独立复审通过。
- 修订源码在独立数据目录完成 3 场原生自然终场：跨存档清理、同存档保留各 1 场，历史客场 `A_0_A` 新种子复测 1 场。输入快照、二进制、日志哈希与终场结果复核通过；复测来源准确保留 `A_0_A`。迁移历史战术副本需同时带上本地完整性文件，缺少时会被正常拒绝。

## 试错与结论

| 现象 | 原因与处理 |
|---|---|
| 偶发 `[WinError 5]`，点继续后正常 | 原版写摘要时直接替换目标文件。测试可通过禁止重命名的读句柄重现同类错误；用户现场的占用进程未知。现版先原子保存暂存摘要，再发布正式摘要 |
| 战术板已汉化，针对性指令和历史事件仍有英文 | 三处页面走不同的显示路径。指令按当前对手名单呈现；事件及 CSV 按该场快照中的主客侧和球员身份匹配译名 |
| 换存档后同一 UID 继承另一生涯的指令 | 原来仅清理对方名单关联，载入方的 UID 覆盖表仍保留。统一在后端绑定时清空跨存档覆盖表，界面同步清理双方，并在比赛准备阶段再次校验来源 |
| 单场复测来源编号总被记成 `B` | 原场次变量被新实验方案循环覆盖。读取原场次时即单独保存来源对象，持久化时不再引用循环变量 |
